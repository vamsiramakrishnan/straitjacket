## The cache question: does the discipline change raise cost while keeping tokens low?

**No — but a naive reading of the matrix says yes, which is why this
needed proper measurement.** S1:sonnet:sj posted 2.9× naive cost with
identical turns/time/output. Wire ground truth (per-request usage, new in
v0.7.1) locates every token of the delta:

- `S1_sonnet_sj` seq3: `creation=56,197, read=0` — the entire prefix
  written cold. The v0.7.1 discipline prompt changed the system-prompt
  prefix, invalidating all previously cached sj prefixes; the first sj
  session per model pays once (~$0.21 sonnet, ~$0.05 haiku).
- `S2/S3_sonnet_sj` seq3: `read=47,313, creation≈9k` — they rode the
  prefix S1 wrote. Amortization is immediate and total.
- Across **every** proxied run in the matrix and study: **zero true cache
  invalidations** (cache_read never regresses within a thread). All
  ongoing `cache_creation` is normal suffix growth that both arms pay.

Controlled study (S1:sonnet, both arms behind the observer proxy, arms
sequential, two rounds inside the cache TTL):

## Honest negatives

- **Haiku + harness on small tasks is a bad trade.** S1:haiku:sj took 2×
  turns/time/output for the same one-line fix; S2/S4:haiku:sj also ran
  longer and spent more. The small model treats harness affordances as
  extra work items rather than shortcuts, and the emission-discipline
  prompt measurably did not reduce haiku's output (S4: 21,348 vs 13,062).
  Discipline text may need model-conditional strengthening, or wrap
  should recommend sonnet-class models for harnessed runs.
- **S3:haiku both arms failed** — the comprehension scenario needs either
  more turns or a better model, so it only discriminates at sonnet.
- **S2:sonnet:sj wrote 4 tests vs naive's 8** (both green, both meeting
  the "including an edge case" bar — but thinner). Emission discipline
  should not be allowed to shade into effort discipline; watch this.

## Benchmark-methodology lessons (recorded so we stop re-learning them)

1. **Any system-prompt change = one cold prefix write per model.** Warm
   both arms (or amortize explicitly) before comparing cost, or the first
   changed-arm cell eats a phantom 3× penalty.
2. **Concurrent arms race for the shared prefix blocks** (tools + system
   are near-identical across arms); whoever's first request lands first
   warms the other arm. Sequential arms + wire observation makes cache
   flow attributable instead of confounded.
3. **The naive arm must run behind the observer too** (bare `ctx proxy`,
   no hooks, no discipline). Aggregate `modelUsage` cannot distinguish a
   cold prefix from churn; per-request wire data can.
4. The only cache metrics that mean anything: **cold_prefix_tok** (one-time),
   **invalidations** (cache_read regression — the true break signal), and
   **ongoing creation** (suffix growth, paid by everyone). A raw
   "cache_creation total" or naive "hit rate" conflates all three.
